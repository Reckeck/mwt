# Подзадачи: Opus планирует и проверяет, Sonnet делает

Роли не меняются по ходу работы:

| Роль | Кто | Что делает | Чего не делает |
|---|---|---|---|
| Планировщик и проверяющий | основная сессия (Opus) | план, разбиение, бриф, проверка, гейт, коммит, отчёт пользователю | не пишет сама то, что можно отдать по брифу |
| Исполнитель | подагент `model: sonnet` (общий тип, `general-purpose`) | правит код строго по брифу, гоняет быстрые проверки, отчитывается | не коммитит, не меняет план, AGENTS.md и скиллы, не расширяет задачу |

В инструментах без выбора модели для подагента (OpenCode, Codex) роли те же:
исполнитель — самая дешёвая доступная модель, проверяющий — основная сессия.

## Когда отдавать, когда делать самой

- **Отдавать:** задача описывается брифом в один экран и проверяется
  командой или снимком — вёрстка по кадру холста, новая команда по скиллу
  `ipc-command`, тест core, ветка мока, локали, раздел docs, набор снимков.
- **Делать самой (Opus):** разбор кадра и решение, куда кладётся код по FSD;
  спорный дизайн; отладка, где причина ещё не найдена (сначала найти причину
  по `debugging-and-error-recovery`, потом отдать починку); схема vault и
  крипта (`vault-crypto`); коммит, гейт, отчёт; правка, которая короче брифа.
- Подзадача дробится по `planning-and-task-breakdown`: одна подзадача — один
  проверяемый результат, обычно 1–5 файлов. Каждая — строкой в списке задач
  с номером, бриф ссылается на этот номер.

## Бриф (что получает исполнитель)

Исполнитель начинает с нуля и не видит разговора. Бриф самодостаточен
(`context-engineering`): всё, что нужно, — внутри или путём к файлу.

```
Задача #<N>: <одна строка — результат, а не действие>

Рабочая копия: ~/apps/work-app-ui-redesign (jj; cwd сбрасывается — всегда cd).
Прочитай до правки: AGENTS.md, скиллы <список>, файлы <путь:строки>.

Что сделать:
1. ...
Как должно выглядеть / работать: <кадр холста, путь к копии, тексты дословно>.

Критерии приёмки (все проверяемые):
- [ ] ...
- [ ] быстрые проверки зелёные: pnpm biome check --write src scripts;
      pnpm vue-tsc --noEmit; node scripts/check-ui.mjs; node scripts/check-fsd.mjs
      (+ cargo test -p trade-core <модуль>, если менялся core)

Нельзя: коммитить (jj describe/new/commit), git commit/add/stash, трогать
файлы вне списка без причины, менять AGENTS.md/план/скиллы, запускать
снимки или mise run check параллельно с другим процессом, менять данные
пользователя, расширять задачу.

Отчёт (последним сообщением): изменённые файлы; что сделано по каждому
критерию; вывод проверок (хвост); что не получилось и почему; вопросы.
```

Правила кода проекта (лимиты `.vue` 250 / `.ts` 300 строк, `meta` у мутации,
локали ru+en, FSD, общие компоненты) в бриф не переписывать целиком —
назвать скиллы и `AGENTS.md`, а в критериях перечислить то, что в этой
задаче легко нарушить.

## Запуск

- `Agent` с `model: "sonnet"` и `description` «#<N> <кратко>». Подагент
  работает в той же рабочей копии jj — **один исполнитель за раз**, если
  подзадачи трогают общие файлы или запускают Vite (снимки, check-layout,
  гейт делят порт). Параллельно — только независимые по файлам и без
  запуска сервера.
- Не `isolation: "worktree"`: AGENTS.md запрещает git worktree в этом репо.
- Пока исполнитель работает, планировщик не правит те же файлы; можно
  готовить бриф следующей подзадачи или читать кадр.

## Проверка (что делает Opus после отчёта)

Отчёту не верить на слово — проверять по факту (`code-review-and-quality`):

1. `jj diff --stat` и `jj diff <файлы>` — только то, что в брифе; нет
   посторонних правок, отладочного кода, `// DEBUG`, закомментированного.
2. Сама перезапускает быстрые проверки (не берёт вывод из отчёта).
3. Вёрстка — снимки `mise run shots -- <set> --only <name>` на 1280 и 390,
   смотрит пары «холст | приложение» через Read.
4. Логика — по коду: граничные случаи, ошибки, доменная арифметика только
   в `crates/core`, тексты дословно с кадра, обе локали.
5. Решение:
   - **принять** — отметить задачу выполненной;
   - **вернуть** — `SendMessage` тому же исполнителю со списком конкретных
     замечаний (файл:строка → что не так → что ожидается); не больше двух
     возвратов, потом доделать самой и записать почему;
   - **откатить** — `jj restore <файлы>`, если результат не годится, и
     переписать бриф (обычно причина в брифе).
6. Отклонения от холста — в `docs/ui-redesign-vs-canvas.md` (пишет тот, кто
   правил, проверяет Opus).

Гейт (`cargo fmt` + `mise run check`), коммит (`jj-workflow`,
`commit-coauthor`) и отчёт пользователю — только планировщик, после
проверки всех подзадач этапа. В отчёте пользователю — какие подзадачи
делал исполнитель и сколько было возвратов.
